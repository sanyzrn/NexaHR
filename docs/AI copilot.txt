## Verified correct
- **Registration is fail-closed now.** `tool()` raises at import for any spec declaring neither capabilities, roles, nor `guarded_inline=True` (`base.py:151-158`); duplicate names raise. The default-open hole you already found cannot recur silently.
- **Advertised == executable, on both paths.** `allowed_tools` filters with the same `is_allowed` that `guard` enforces; `guard` re-runs inside `execute_tool` at execution time (`base.py:333`) and *again* at confirm time with the confirmer's **today** caps (`confirmations.py:94-104`); the write switch is enforced at execution, not just advertisement (`base.py:336-340`) — H-1 stays closed for both the turn loop and the confirmation point.
- **Every write tool is `risky=True`.** Verified by enumerating all 47 registrations: there is no write path that bypasses the pending-action card. The card's summary is produced server-side from raw arguments (`summary_of`/`describe`), never from model prose — so injected spreadsheet text can re-propose an action but cannot relabel what will execute.
- **Single execution.** `_claim_for_execution` uses an atomic conditional `UPDATE … WHERE status='pending'` committed *before* the runner runs; concurrent/double confirm gets 409 (e2e step 12 proves it live against the running server); failed executions roll back partial writes and record `ai_action_failed` (H-3 closed). Expiry is tz-aware `timestamptz` compared against `datetime.now(UTC)` — no naive/aware crash.
- **Workflow parity is real.** `advance_evaluation` delegates each action to the actual endpoint function with real Pydantic payloads; the `_ADVANCE` table reproduces `require_chain_stage`/`require_roles` semantics including the `hr_claim` exception (no transition, role gate would otherwise be skipped). `apply_transition` independently re-checks role, assignee seat, `ensure_hr_may_handle`, no-finalize-without-result, and no-finalize-without-snapshot. `create_evaluation`'s body re-checks `may_act_at` + the scorer seat (`routers/evaluations.py:377-380`), so the bypassed `Depends` is compensated in-body. `ceo_finalize`'s background tasks are executed inline so the hashed PDF is actually produced.
- **Endpoint-delegation tools checked one by one:** `update_user` → `users.update_user` (self-lock, open-chain-seat guard, `revoke_all_for_user`, `must_change_password` all inherited); `grant_capabilities` → `administration.set_capabilities` (last-holder-of-manage_capabilities and employee-refusal inherited); `create_indicator`/`update_indicator` → indicators router (`_publish` versioning + wording-fix 409 inherited, with `wording_fix_reason` plumbed into the schema); `create_period`, `period_progress`, `create_improvement_plan`, `add_evaluation_comment` (the `ensure_hr_may_handle` fix holds), `separate_personnel` → `_close_out_departure`.

- **Read scoping:** `search_evaluations` and the context record block use the exact `scope_evaluations_for_role` allowlist (unknown roles raise — fail-closed); `get_evaluation` uses `_ensure_can_view`; `search_personnel`/`get_personnel` scope by `EvaluationAccess` seats + self; `search_users` and `list_user_capabilities` mirror their endpoints' `manage_users`/`manage_capabilities`; analytics tools mirror `require_roles(hr)` / `(ceo, deputy)` / `(unit_supervisor, deputy)` exactly; `search_audit_log` mirrors the UI's full-vs-`SYSTEM_EVENT_TYPES` split including the `evaluation_record_id is None` belt; `inspect_upload` is ownership-scoped on both `user_id` and `conversation_id`.
- **Spend limits exist and bind:** per-user daily message cap (0 → global default 100, −1 explicit unlimited) enforced in `/chat`; 20/min rate limit; `max_user_chars`; `max_tokens` with truncation detection that *aborts* half-written tool calls instead of executing them; `max_tool_iterations` (default 6, schema-capped 1–12) with `tool_choice="none"` on the final step.
