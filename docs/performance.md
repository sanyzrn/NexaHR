## Verified correct

- **The suspected N+1s in the list/aggregates are genuinely fixed.** `list_evaluations` (`evaluations.py:626–693`): one COUNT, one page query, one *batched* audit query for `was_returned`; `subject`/`hr_user` are `lazy="joined"`; server-side pagination (limit ≤ 200). Measured **12–20 ms** at 3.5k records. `dashboard.overview` aggregates fully in SQL — `row_number()` window for the outcome mix, `count(distinct)` cohort suppression, EXISTS for open-evaluation flags — measured **22–78 ms**. `analytics.executive_overview` and `reports.summary`: **10–15 ms** (the executive endpoint pulls one float per finalized record for median/p90 — bounded, one column).
- **Indexes match what actually ships.** Dumped `pg_indexes` from a fully-migrated DB: all four seat FKs, subject, period, `status,created_at`, `final_weighted_pct`, `stage_entered_at`, `verify_token`, open-objection partial, audit `event_type/created_at/record`, personnel `org_unit/status` — all present and declared on the models (so autogenerate can't propose dropping them). The only unindexed shipped filters (`personnel.contract_end_date`, `evaluation_access.unit_supervisor_user_id`, `%ilike%` name search) sit on headcount-sized tables where the measured seq-scan share is <2 ms — no missing-index finding survives rule 5 at this product's scale.
- **PDF is off the finalize request path.** `ceo_finalize` (`evaluations.py:931–956`) commits the record, then `archive_final_pdf_detached` renders in a `BackgroundTask` with its own session and a sweeper backstop; the duplicate-render race is handled by SAVEPOINT + unique constraint (`documents.py`). Measured warm WeasyPrint render: **182 ms/doc (25 KiB)** — even the legacy in-request archival in `/summary.pdf` (first download only) is cheap.
- **Frontend bundle and re-render behaviour are sound.** All routes `React.lazy` (`App.tsx:12–74`); recharts isolated in a lazy 381 KB chunk (`PersonCharts`), only fetched where charts render; entry chunk 377 KB (**114 KB gzip**); `DashboardPage` 58 KB, `EvaluationDetailPage` 60 KB. Search debounced 300 ms with server pagination (default 10/page); `ScoreForm` explicitly guards its init effect against the autosave loop (`ScoreForm.tsx:91–99`); notification polling is visibility-aware (5 s visible / 60 s background, 15-row payload).
- **Other exports and the audit view.** Audit export caps at 5,000 rows and builds without an intervening commit (no expiry N+1); report export aggregates first and builds from plain values. `list_audit_log` resolves usernames/codes by JOIN, not per-row loads. `_SafeSheet` applies the formula-injection guard on every sheet at negligible cost. DB pool is explicitly sized with `pool_pre_ping` and exposes `pool_stats()`; scheduler sweeps run in `asyncio.to_thread` under an advisory leadership lock.
- **Paired-invariant spot check (performance side):** `IS_OPEN_RECORD` (`status IN (4 open values)`) is logically equivalent to the partial index predicate `status NOT IN ('finalized','cancelled')`; Postgres won't prove that implication, but every open-record EXISTS probes `ix_evaluation_records_subject` instead, so no query is left unindexed.
